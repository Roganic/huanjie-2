## 玩家可以得到什么

- 自然语言表达目的，由模型选择当前场景已有的移动、交谈、调查、背包、休息或战斗操作；调查沿用模组定义的技能、难度和后果。
- 可以追问 NPC，回应使用人物身份、性格、允许透露的知识及该人物近期对话；正式线索、委托和奖励仍通过实际交谈逻辑触发。
- 模型可先查看当前场景对象或在场人物，再选择行动；每轮最多执行一个玩家行动。复合行动提示先选择一项。
- 原始行动结果始终显示，AI 的语气与氛围描写单独显示。文字返回 SSE 适配事件，但本版不是供应商逐 token 流式输出：回应校验后才展示。
- 模型不可用时：未执行的自由输入明确提示未消耗资源，已完成的行动保留结果并显示固定裁定。未配置模型时，原有固定玩法和按钮照常可用。

## 权限表

| 能力 | 授权来源 | 程序边界 |
| --- | --- | --- |
| 语气、姿态、氛围 | 角色设定与当前已知事实 | 不写入背包/任务/地图 |
| 查询 | 当前场景和在场和平活人 | `inspect` 无法读取其他地点或不存在的人物 |
| 人物知识 | `characters[*].knowledge[*].required_flags` | 未满足条件的文本不进入提示词 |
| 玩家行动 | 当前场景的操作目录 | `act(action_id)` 只接受目录内 ID，无任意命令/数值参数 |
| 检定/伤害/奖励 | 现有模组和规则引擎 | 共用 `execute_command`，AI 无权填写骰点、DC、伤害、奖励 |
| 友方/中立攻击 | 当前政策禁止 | 目录不提供，明确攻击输入预先拦截，底层仍检查目标权限 |
| 新任务/关键物品/地点/永久分支 | 后续设计 | 当前无相应写入工具 |

自由文本语义无法靠格式和关键词校验百分之百保证正确。当前通过信息筛选、权限提示、现有矛盾检查及拒绝明显数值/奖励越权降低风险；原始裁定保留。未声称已经解决任意幻觉、剧透或输入诱导。

多动作输入的“先追问”属于模型指令；程序额外保证每轮最多一个状态操作，防止错误理解变成连续执行。是否准确理解玩家意图、是否合理拒绝不支持的办法，仍需真实模型样例评测。

## 实现边界

- `src/gm/provider.py`：Chat Completions Function Calling 兼容适配，配置仅在服务端读取。不引入 LangChain/LangGraph；当前三个工具为 `inspect`、`act`、`respond`。
- `src/gm/context.py`：从当前内容与状态生成操作目录，按人物知识条件筛选。不会把整份模组、未发现互动的成功/失败奖励或全部未来任务路线发给模型。
- `src/gm/host.py`：每轮最多 4 次模型调用、2 次只读工具、1 次状态操作；总模型等待预算 35 秒，单次 HTTP 超时至多 18 秒。单次输出上限 800 tokens；消息 JSON 上限 24,000 字符，玩家输入上限 1,500 字符。字符预算不是精确 token 预算。
- 查询完成后重新核对会话版本，再调用原子命令服务。模型调用期间不持有全局游戏锁。状态变化则拒绝过期执行。
- 核心结果和原始请求回执先落盘，再请求叙事。模型失败/请求中断后重试同一编号可返回既有裁定，不重掷、不重复扣物品；已保存但未完成的回应标记 `pending`。
- 最终叙事只补写对应回执、记录，不用旧快照覆盖新状态。存档/重启保留 `gm_turns`、历史中的 `gm_narration/gm_notice`。
- 会话保存最近 40 条 GM 交流，普通提示取最近 8 条，NPC 回应取该人物最近 6 条；长期关键事实始终从任务、线索、世界状态读取。不是无限历史记忆，也没有把模型总结提升为游戏事实。
- 模型输入/输出 token 使用量、工具名、选择的操作 ID 和失败原因随回合保存；不记录密钥或供应商原始错误正文，不保存模型隐藏推理。

## 配置与切换

将 `app/backend/gm.env.example` 复制为 `app/backend/.env.gm`，填入：

- `GM_API_STYLE`：`qwen`（发送 `enable_thinking=false`）、`deepseek`/`kimi`（发送 `thinking.type=disabled`）或 `standard`。
- `GM_API_URL`：供应商控制台给出的完整 Chat Completions 地址，含 `/chat/completions`。地域和业务空间须与密钥一致。
- `GM_MODEL`：模型调用 ID；必须支持 Function Calling。推荐初测 `qwen3.7-flash-2026-07-15`，见模型调研。
- `GM_API_KEY`：仅本地填写。该文件被 Git 忽略，不使用 `VITE_*` 保存密钥。
- `GM_ENABLED=false` 可回到固定主持。

配置后可在 `app/backend` 运行 `.venv/bin/python scripts/check_gm.py`，仅发起一次真实工具调用验证连通性，不读取或修改冒险进度。

环境变量优先于文件；下次请求读取新配置，无需重新建角。配置有效仅表示必填项齐全，不等于连通性/模型效果已验证。页面显示“AI 主持已配置”或“固定主持 · AI 未配置”，单次失败另行提示。

顶部模型设置页复用本地配置边界，支持真实连接测试、更换模型、启用/关闭。密钥留空保留、更换地址需新密钥；本机来源校验、错误脱敏和原子写入已实现。详见可玩版说明。

内置内容 1.2.0 增加老马库斯、托尔金等人的性格和有限个人知识，不改变原任务奖励和地图。已有会话固定旧内容快照，可使用 AI 对话和已有资料，但要使用新人物设定需从模组面板启动 1.2.0 新冒险。

## 验收

后端全量 692 项通过（保留 7 条既有依赖弃用警告），前端构建/lint 通过。新增 21 项集中在工具权限、回执/中断、状态并发及对话持久化；没有用测试数量代替模型效果验收。独立浏览器使用标明“模拟主持”的响应，验证生成段落/真实裁定并列、刷新恢复、资源保持不变，未记录脚本错误；未操作用户原冒险。

已通过隔离的协议与游戏规则检查：

- 模型查询→选择交谈→回应→追问→手动存档→重读恢复。
- 自由表达映射到真正的石门调查，沿用原难度、骰点与场景时间。
- 隐藏知识不进入提示词，锁定互动/不存在的工具/额外数值参数不可执行。
- 友方攻击在调用模型前拒绝；战斗只执行选定一次动作，敌方自动回合遵循原规则。
- 连续查询到上限即停止；模型超时、失败、重复编号、执行后中断、状态过期都不重复消耗资源。
- 前端保留原始裁定，显示生成回应与失败通知；刷新恢复叙事。

后续模型比较继续使用同一批问题：意图识别正确率、NPC 信息一致性、无依据承诺/剧透、追问连贯性、P50/P95 响应时间及每轮实际 token 消耗。本轮真实测量见可玩版报告，不把格式通过或状态正确当作所有对白正确。
