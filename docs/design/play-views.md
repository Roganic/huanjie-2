# 文字版与美术版

2026-09-10，本地实现。游戏顶部的“文字版 / 美术版”直接切换布局。未设置偏好时默认美术版，之后在当前浏览器记住选择。此偏好独立于模组皮肤和冒险存档。

## 两种布局

| | 文字版 | 美术版 |
|---|---|---|
| 桌面 | 左侧角色、中央大幅叙事与操作、右侧场景与地图 | 左侧角色肖像、中间场景大图与地图、右侧旅行手记 |
| 内容 | 紧凑排版、纯文字装备与人物按钮、无场景插画 | 保留已有插画、肖像、地图底纸和书页表现 |
| 手机 | 顶部紧凑场景与人物，下方叙事与行动 | 顶部场景画面，下方叙事与行动 |
| 地图 / 战斗 | 同一个可操作地图和先攻队列 | 同一个可操作地图和先攻队列 |

两种布局共用任务、角色、背包、模组、创作和菜单。窄屏角色信息仍可从顶部“角色”查看；场景全文仍可在“此地景象”展开。文字版的路线区允许滚动，避免相邻地点较多时被截断。文字版保留地图图标，并非只剩聊天框。

## 状态与实现约定

- `interface.ts` 维护展示偏好，保存于 `localStorage['huanjie.presentation']`，仅允许 `text` / `illustrated`。未知值回到美术版；偏好写入失败也不妨碍当前切换。
- 主 `AdventureController`、主 Phaser 场景、输入框、历史正文和行动控件共用，不复制业务分支、不重建冒险、不重新取状态。切换不消耗游戏时间、不发出命令、不调用模型。
- 保留输入内容与选区、正文展开状态、地图选点、战斗目标、创建角色表单、地图浮窗/关闭状态。正文按切换前滚动比例恢复阅读位置，文字换行变化时不保证像素位置相同。
- 等待回应时切换按钮仍可用，游戏行动维持禁用。原命令完成后正常更新当前布局；期间另写的草稿不会被原请求清空。
- `adventureEngine.ts` 只启停独立的装饰场景引擎。文字版不创建主界面的肖像/装备图片，不运行场景插画；地图和先攻引擎继续工作。切回美术版按当前场景重新加载画面，可能有短暂加载过程。
- `presentation.css` 负责双视图排版，已有模组主题变量继续复用。本轮没有重启旧 React 游戏页，也没有维护两套玩法。
- 偏好在本浏览器内保存，不做账户同步。页面刷新会保留布局偏好；输入草稿仅承诺布局切换时保留，不新增刷新恢复机制。
