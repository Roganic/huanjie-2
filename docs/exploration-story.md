## 玩家路径

先在酒馆与老马库斯交谈，向东到地下城入口找托尔金，接取“地下城通道的隐患”。两条路线任选其一：

| 路线 | 行动与后果 |
| --- | --- |
| 清理敌人 | 向北进入通道 → 按先攻与全部敌人战斗 → 清场后返回托尔金处交付 |
| 调查示警 | 调查入口石门 → 找到夹层并取出巡逻记录 → 经村庄广场回酒馆与老马库斯交谈 → 村民收到警告后，回入口向托尔金交付 |

- 调查石门需要先听取托尔金的说明，使用调查技能、难度 10。成功找到夹层；失败消耗 1 格场景时间，不掉血、不发线索，可以重试或选择战斗路线。
- 取出巡逻记录需要先找到夹层，无需投骰，消耗 1 格时间。记录保存在已知线索中，不是可交易的背包物品。
- 回酒馆示警是一次性事件；没有巡逻记录时，普通交谈不会提前触发它。
- 两条路线共用一份委托状态，都在托尔金处领取治疗药水 ×2，奖励只发一次。非战斗路线不授予击败敌人的 XP，不修改敌人生命值、不标记清场；之后进入通道仍会发生遭遇。
- 攻击托尔金仍会中止未完成委托。先示警再清场也不能重复领取委托奖励。
- 已有补给箱和碑文互动保留，作为可选调查，不强制走主线。

## 界面与行动规则

场景指引展示人物、出口及互动卡片。每张卡片给出“待解锁 / 可互动 / 已完成”、前置提示、检定技能/难度与时间成本。已完成互动保留在界面，避免玩家误以为对象凭空消失。

按钮提交稳定的 `interaction_id`；文字按当前场景中的行动名称、对象名称和别名匹配，最终进入同一个处理函数。支持“调查石门”“检查石门”“我想调查石门”等确定表达。不能通过客户端传入的角色、场景、属性或难度覆盖内容定义。

无法识别的目标、否定句与串联多项行动不会进入默认力量检定。系统说明没有匹配到处理方式，并列出当前操作；不会消耗时间、生命或奖励。观察周围只描述现有场景与行动。背包、移动、普通交谈、职业能力和真实战斗仍走各自已统一的服务。

这不是通用自然语言理解：匹配规则是确定的，任意说服、欺骗、自由生成世界及未配置对象仍不支持。保留的旧规则编排器不再作为网页 `/action` 的兜底。

## 内容与接口边界

内容仍位于 `ModulePack`，进度仍存于现有会话，无第二套任务状态服务：

- 互动新增 `aliases`、`required_flags`、`set_flags`、`locked_reason`；`skill` 为空表示确定成功的已配置行动。
- 事件新增 `on: interact`，目标使用 `场景ID:互动ID`，校验器拒绝不存在的引用。
- 清场委托可配置 `alternative_flags`、替代目标和实际结果说明，以及按已有标记选择的阶段提示。当前只支持“清场或满足一组标记”的替代完成条件，不是完整分支任务图。
- `GET /exploration` 的 `objects` 返回全部互动与状态；兼容 `interactions` 列表只返回当前可用项。
- `POST /action` 接受可选 `interaction_id`；对象必须属于当前地点。流式与普通响应使用同一裁定结果。
- 线索、前置标记、已触发事件、已完成互动和任务随存档保存。调查的骰点、难度、成败及下一步提示也写入历史，刷新/读档后不会变成“自动成功”。旧历史如果只有 `result`，前端仍能恢复其成败。
- JSON Schema 已同步到 `docs/module.schema.json`。未来编辑器和文本解析器仍只负责生成与校验此内容格式。
