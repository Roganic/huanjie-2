# 自由行动理解与裁定：实施与人工协作

2026-09-10。用户确认按“先统一行动与规则能力 → 建立表达评测 → 比较小模型”的顺序推进，并安排策划参与。此文是实施基线；协作材料已经落地，以下新理解链路尚未接入运行，不能据此声称意图质量已经提升。

## 目标与现状

目标：准确识别玩家的表达方式、对象、目的、方法与资源诉求，把有意义的行动落到已有操作或可组合的目标契约；不强行让每句话掷骰，不为匹配成功替换玩家意图。

现状：`gm/host.py` 已调用工具规划，`adjudicate` 已支持目标、做法与后果选项，`game/adjudication.py` 冻结成败契约，`game/commands.py` 原子结算和幂等重放。缺口是理解结构分散、规则目录会影响意图选择、默认模组具体社交目标稀少，以及缺少经过人工确认的表达评测。

通用社交当前主要影响好感，不能代替借物、获取特定线索或争取任务支援。默认模组商人尚不交易；友方/中立攻击仍禁用；没有战斗距离、警戒或察觉系统。本次不暗中恢复它们。

## 阶段一：统一行动与可组合目标

技术工作按下列顺序实现：

1. **统一提案结构。** 保留玩家原话与本轮上下文，分离表达模式（执行/询问/表达/取消/待澄清）、对象、目的、方法、所需资源和未确定项。提案只是请求，不带可直接写入的奖励、骰点或事实。
2. **上下文解析。** 使用最后明确指代、已结算行动、待澄清请求与当前场景/战斗状态；区分“我有某物”的自述与真实背包。换场景后重新核对指代，不用关键词猜测未指明对象。
3. **统一能力候选。** 复用已有命令、交互、ChallengeDefinition、approaches 和 consequences；候选标明目标、条件和不可执行原因。保留“不支持”的真实意图，不能把被禁止的攻击改成聊天。只提供玩家可知的对象和目标，不泄露隐藏分支答案。
4. **规则适配。** 目标契约确定能否执行、是否检定、资源成本与后果，检定前冻结计划。已有 authored challenge 优先；通用模板只组合明确允许的对象能力和后果。禁止任意生成新秘密、物品、任务或奖励。
5. **接回现有模型。** 现有工具循环使用统一提案；复用已有预算、超时和修复上限，不增加每句话必经的模型调用。模型不能绕过统一命令入口。按钮继续快速结算。
6. **先审计再切换。** 在隔离测试冒险中记录新旧理解差异；新理解器出现歧义时复核或澄清，不直接执行。通过后再使样板冒险启用新路径，旧档与原规则快照保留。

人工输入：审改 8 张目标卡，确认每个目标的允许方法、自动成功条件、禁区、成败后果、重试与失败后的可继续路径。策划不用写 JSON、提示词、接口或检定程序。

无需等人工的部分：统一数据结构、旧命令适配、只读候选整理、原有事实与资源校验、幂等/重试保护、隔离验收环境。依赖人工的部分：新增目标的奖励/惩罚、物品交付、秘密披露、任务承诺以及玩法平衡；未确认部分作为独立草稿，不进入默认冒险。

完成条件：选定样板中的目的性行动能经统一提案进入同一结算通道；有依据地区分自动处理/检定/拒绝/澄清；至少覆盖普通聊天、两种方法达成同一目标、证据满足条件、失败后推进、否定/询问不误执行。人工确认的内容才能成为默认玩法。

## 阶段二：表达评测与体验修正

- 首批 30 条样例已预填，全部是助手编写的合成草稿，不是玩家统计，也不是已审批标准答案。
- 策划审改这 30 条，再新增 30 条：10 条开发可见、20 条作为暂不公开的验收题。20 条在提示词和规则冻结后才交给技术执行；预期答案不送入模型。
- 每条记录原话、真实上下文、合理解释（允许多种）、目标、方法、是否执行、是否检定、禁止出现的错误。不强求唯一措辞或唯一技能；不明确的题可以期望澄清。
- 近义改写、同一原句衍生句、同一多轮对话作为一组划分，不能拆到训练与验收两边。重复动作输入还应区分相同请求重放与一次新的尝试。
- 不只有单句：至少包含否定、引号转述、间接请求、指代、改口、复合动作、失败重试、资源虚报和受限攻击。样例上下文保持够用但不泄露答案。
- 输出分别统计：意图/对象/目的/方法错误、目录漏召回、规则不支持、规则结算错误、叙事与事实冲突，以及端到端耗时与实际 token/费用。不能把所有问题归为“模型不聪明”。

建议首轮验收门槛，交策划/产品确认：固定关键用例中误执行、重复发奖、凭空物品/线索为零；合理解释命中率至少 90%，按类别报告分母和澄清率。20 条盲测只是首轮放行检查，不是泛化可靠性的统计证明。不能通过把所有输入都判为澄清来获得通过。

人工输入：表达标注、疑难句裁定、真实试玩中的自然度与后果公平性评价。算法评测与回归由技术完成，不要求策划维护自动化测试。

## 阶段三：比较与接入轻量理解器

在相同人工确认用例上比较：现有模型基线、候选检索/排序、小模型理解、低确定性时升级复核的混合方式。语义检索只找候选，不能凭相似度直接执行；模型自报置信度不能当作已经校准的正确概率。

分别测目标/对象识别、否定及指代错误、误执行、澄清比例、模型调用次数、端到端中位与高分位延迟、实际 token 和总成本。比较必须计入升级复核与叙事请求，不能只报小模型推理耗时；区分冷启动和已加载运行。

小模型作为可替换的理解器实现，不改变游戏规则或存档接口。叙事 LLM 仍收到玩家原话与权威结果；不无条件再做第二轮完整意图理解。混合方案胜过基线才替换，否则继续使用现有模型。

人工输入：策划提供未用于调参的新表达、对匿名展示的两组结果评价自然度/误解程度；用户决定最终机器是否常驻及成本取舍。技术负责部署、日志、指标与回退。当前不启动家用 GPU、不下载模型、不购买套餐，不因“自部署”预设更快或更便宜。后续付费比较仍受既有总预算约束。
