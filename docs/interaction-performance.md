# 交互性能与游戏界面重构

2026-09-08。保留 React 与现有规则引擎，把明确操作移出模型等待路径；主画面集中显示场景、叙事与输入。角色、冒险记录、模型设置和模组按需打开。原冒险与内容包无需重建。

## 操作分流

| 输入 | 模型行为 | 游戏结果 |
| --- | --- | --- |
| 移动、装备/卸装、拾取/使用、休息、攻击/战斗、离开战斗按钮 | 0 次调用，甚至不创建模型客户端 | 规则结算、事件触发、存档与回执后立即返回 |
| 已声明的场景互动、挑战按钮 | 0 次调用 | 已编写的场景反馈、检定、关系和事件结果 |
| 交谈按钮 | 省去意图规划，规则交谈后生成一次对白；不合格时仍允许一次修复 | 人物知识、线索与任务仍由服务决定 |
| 自由输入 | 模型理解意图；若选择移动/战斗/装备等常规操作，直接显示规则结果 | 通常省去结算后的第二次叙事调用 |
| 自由输入对话/互动/挑战 | 保留规划与结算后的叙事；可能查询或修复 | 不为了减延迟让模型提前编造结算结果 |

共同的 `execute_command` 仍负责权限、状态版本、事务回滚、请求编号与持久化。直接路径也返回 `gm.calls=0`。模型不可用不影响明确的按钮操作；没有增加后台写世界状态的叙事任务。

交谈按钮传入 `kind=talk`、真实人物 ID 与玩家原话；互动按钮传入 `kind=interact` 与真实互动 ID。自由输入继续走 `kind=text`，不通过关键词伪装为直接操作。旧客户端的 `interaction_id` 入口也保留。

前端统一接收 JSON；删除将完整 JSON 再包装成 SSE 的适配，以及探索/战斗两套无效的流解析逻辑。原请求编号保存、断线恢复和完整回执检查保留。

## 界面与交互

- 顶部保留生命、防御与地图/背包/角色/冒险记录，保存、读取、模型设置、模组、重新建角集中到菜单。
- 场景显示当前位置、和平/危险、当前目标与相邻出口；人物互动、其他尝试、任务线索只展开一组。窄屏的完整场景描写可在冒险记录查看。
- 叙事保留正文和简短检定结果；骰点算法、成本、拒绝详情和模型降级原因放入“规则记录”。普通行动不再反复显示“自动成功”。旧拒绝记录也使用简短摘要，原理由仍可展开。
- `feedback.summary/detail` 区分玩家提示与规则详情，不改世界事实；新历史保存 `command_kind`，明确按钮不再恢复成重复的玩家对白。
- 叙事只滚动自己的区域。读旧消息时保留位置，新消息提供“查看最新回应”。输入支持中文输入法，模型等待时可以准备下一句。
- 等待提示放在输入区旁，不遮住内容。等待/连接不确定时能查看面板；会改变状态的按钮暂停，确认原请求结果后继续。
- 角色/冒险记录使用侧面板；背包、读档、模组共享焦点约束、Esc 与关闭后的焦点恢复。地图保留可移动、缩放、调大小的浮窗。
- 战斗参与者卡片缩小，先攻明细可展开；目标、技能和输入固定在底部，战况区域独立滚动。
- 事件完整进度放到冒险记录；当前地点临近的实际后果或紧急事件才在主画面提示。单纯重试间隔不会常驻主画面。
- 375/768/1024/1440 宽度核对无横向溢出，战斗按钮始终在视口内；支持键盘焦点和减少动态效果偏好。

完整报告 `/tmp/huanjie-interaction-acceptance.json`。普通 pytest 不消耗模型额度。现有 `/gm/metrics` 仍统计主持回合，不是所有按钮的性能看板；直接请求用结果内的调用数与独立验收测量核对。

## 边界

本轮不改变判定、关系与重试条件，不扩大 AI 的创作或奖励权限，不实施模组编辑器/纯文本解析器。自由对话仍可能需数秒，依赖模型的理解和回应质量；这次主要消除了日常明确操作的不必要等待。后续内容覆盖与主持能力继续沿用现有契约。
