# OSE 规则分析

阅读顺序：先看“结论”，需要推进实现时再看“保留项”和“排除项”。

本文件关注一个问题：OSE 有哪些特征适合提炼进 AI 跑团的第一版规则内核。

## 结论

- OSE 最值得吸收的是简洁、资源压力、低例外密度和清楚的裁定边界
- 不应直接照搬 OSE 的旧式细碎流程和分散判定表达
- 第一版应做“OSE 结构 + 现代化输入输出”，而不是复刻 OSE

## 为什么适合 AI 跑团

- 规则短，模型更容易在长对话中维持一致执行
- 资源和风险都很明确，便于系统做结构化状态更新
- 对行动宣言和环境互动的重视，适合 AI GM 做场景推进
- 相比重构筑、重连锁的系统，OSE 更不容易把流程拖进复杂例外

## 应保留的 OSE 特征

### 1. 行动优先

- 先让玩家说做什么，再判断是否检定
- 检定不是默认动作，而是处理不确定结果的工具

### 2. 探索压力

- 时间推进要有成本
- 补给、照明、负重、休整都能形成决策张力
- 这类压力比纯数值 build 更适合 AI 主持的持续体验

### 3. 低例外密度

- 同一类场景尽量用同一套判定方式
- 规则少意味着模型更容易保持稳定，不必频繁“翻书”

### 4. 快速战斗

- 战斗应该是高风险、短结算，而不是冗长的技能联动拼图
- 这样更适合聊天式交互和 agent 编排

## 不应直接照搬的部分

### 1. 分散的旧式判定口径

- 如果不同场景分别使用不同底层判定法，会增加模型执行成本
- 第一版应统一成少数几种可预测的判定接口

### 2. 依赖大量人工裁定的隐性规则

- 人类 GM 可以临场兜底，但系统实现需要明确输入输出
- 所以需要把“裁定空间”收敛成少量模板，而不是完全自由发挥

### 3. 过度原教旨的旧派体验

- 纯旧派表达对现代玩家并不友好
- 需要借用现代 d20 语言降低学习成本，例如属性修正和优势 / 劣势

## 建议保留到 V1 的模块

- 统一属性检定
- 优势 / 劣势三态修正
- 轻量战斗循环
- 基础状态效果
- 资源与时间推进
- 简单恢复与成长

## 建议延后的模块

- 完整法术系统
- 大型职业分化
- 精细负重公式
- 复杂遭遇平衡工具
- 高频随机表驱动的子系统

## 对实现的直接启发

- 规则引擎应该接收结构化行动，再返回结构化裁定结果
- GM agent 应把重点放在场景描述、后果表达和选择展开
- 需要单独设计“探索节拍”数据，而不是只处理战斗回合

## 未决问题

- V1 是否保留传统六维属性，还是缩成更少的属性组
- 资源压力要做到什么程度才不会拖慢本地 Web 原型体验
- 社交与调查是否复用统一检定，还是再加独立流程层
