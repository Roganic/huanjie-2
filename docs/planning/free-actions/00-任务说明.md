## 这次要解决什么

让玩家“想达到的目的”能被准确理解并形成合理回应；可以交谈、自动完成、触发检定、说明障碍或澄清。不是把所有话都变成检定，也不是把所有成功都变成好感 +1。

首批范围限定为《灯笼酒馆与遗忘地下城》的**酒馆和地下城入口**，同时覆盖多轮对话。先打磨这两个地点，不要求重写整个游戏或 D&D 规则书。

技术负责人会把文字设计转成规则契约、事件、样本文件和自动检查。策划只对玩法含义和预期结果负责；数字可先写“低/中/高风险”及理由，由技术提出初值再一起复核。不要求没有依据地填写精确 DC。

## 人工必须决定的内容

1. **对象的边界。** NPC 知道什么、不知道什么、愿不愿意提供什么；不能因为某人“神秘”就默认他藏着秘密。
2. **真实目的。** 玩家是在询问、行动、开玩笑、转述、取消还是表达情绪；有两种合理解释时哪些都可接受，何时应追问。
3. **成败体验。** 成功具体实现什么；失败付出什么；成功是否仍有成本；是否会堵死主线；是否存在替代路线。
4. **玩法取舍。** 哪些做法合理、哪些暂不支持，重复尝试需要什么变化，人物拒绝是否合理。

技术负责对象 ID、接口、语义检索、模型服务、提示词、骰点计算、库存核验、存档与请求重放、计费及性能。不要把这些工作转交给策划。

## 交付检查表

- [ ] 每张目标卡都有范围、条件、自动处理/检定/拒绝/澄清的区分。
- [ ] 需要检定的目标有明确成功与失败后果；失败后还有可玩的方向。
- [ ] 同一目标的方法有真实区别，不只是同义词；不适用多方法的普通问答无需硬凑。
- [ ] 涉及物品/线索/支援时，写明来源、数量或信息范围、能否重复取得。
- [ ] 表达样本写了上下文，不让标注者猜“他”“再一次”指谁或什么。
- [ ] 没把玩家口头声称的道具、证据、击杀当成既成事实。
- [ ] 新玩法与现有规则分开；暂缓项不被当成默认开放。
- [ ] 已记录姓名/日期和仍有分歧的条目。

## 固定约束与沟通

友方和中立 NPC 暂不允许攻击；没有战斗站位、距离、警戒或察觉系统；默认商人当前不交易。可以准确理解这些意图后给出限制，不能偷偷改成聊天或好感检定。若策划希望改变这些产品约定，请写为“另议建议”，不要混入本批通过项。

文件里标有“现状”的部分来自当前规则；标有“建议”的内容由助手预填，**尚未经过策划审批，也没有写入实际模组**。先审前 4 张卡即可推进第一轮联调，剩余卡和表达样本分批交。
