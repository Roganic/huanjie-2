# 试玩、盲测与回传

## A. 自己准备 20 条盲测表达

在技术版本冻结前，先不要把题目交给提示词调优人员。不要照抄 02 文件换一个名字；至少包含 4 段多轮对话，以及下列容易误判的情况：否定/取消、询问玩法而非执行、对 NPC 的间接请求、转述或引号、切换对象、失败后的换方法、缺失资源、受限攻击、复合动作和信息不足。

每条用下面的自然语言格式写即可：

- 编号：B01。
- 所在场景、在场人物和真实背包/进度：____。
- 前面一两轮的玩家输入、真实结算及 NPC 回应（若需要）：____。
- 本轮原话：____。
- 合理的对象/目的/方法：____。
- 可以接受的多种理解：____。
- 应当：只回答 / 执行动作 / 自动处理 / 鉴定 / 拒绝 / 澄清。
- 必须避免：____。
- 依据哪张已批准目标卡；若当前不支持，说明这是“识别正确后拒绝”还是“新增能力要求”：____。
- 审核人/日期：____。

技术执行时只给理解模型原话、必要上下文与能力目录，不给“合理答案”和“必须避免”列。对同一题的改写放在同一组，不能一部分用于调优、另一部分用于宣称盲测。

## B. 第二阶段：按 10 个任务真实试玩

用技术准备的独立测试冒险；不同成败分支由技术准备独立场景/存档，不要修改自己的正式存档，也不要反复刷骰来追求某个结果。以下为验收任务，不是新增游戏规则。

| 任务 | 做什么 | 观察什么 |
|---|---|---|
| P01 自然问路 | 不用按钮原文，向马库斯问入口、联系人，再用“他”追问 | 对象是否连续，是否只给真实已知信息 |
| P02 问与做 | 先问笔记写了什么，再明确阅读 | 前者没有偷执行，后者能进入正确互动 |
| P03 同目标不同方法 | 对一张批准的目标卡分别用两种允许的方法 | 实际方法/成本有差别，不是两个相同好感骰 |
| P04 前置不足 | 未听刻痕说明就调查石门；再补齐说明重试 | 正确指出条件；条件变化后可继续，不永久锁死 |
| P05 成功与失败 | 用技术准备的两种结果分别执行搜箱或调查 | 成败与卡片一致，失败后有可走方向，叙事不反转结果 |
| P06 间接请求 | 用“你能不能把……给我”表达一项已批准请求 | 能分辨向 NPC 发请求与向系统问玩法；有歧义才澄清 |
| P07 否定/转述 | 说“我不是要打他”或转述别人威胁的话 | 不触发攻击、不擅自减好感、不制造已发生的动作 |
| P08 改口/指代 | 切换人物、说“换个办法”或“算了” | 不继承错误对象；取消未执行的请求不会撤销已经结算的事实 |
| P09 重复尝试 | 同目标换措辞、换技能；再重复发送已完成请求 | 不刷奖励、不重掷已提交请求；新的合法机会能被识别 |
| P10 自由挑战 | 自己提出合理但卡片没写原话的表达 | 能映射到目的和方法；不支持时忠实说明，不偷换成别的动作 |

每个关键问题保留原话与上下文。一般截图不够判断指代；至少记录前一轮和当前场景。

## C. 问题回传模板

```
编号：
版本 / 目标卡编号：
测试角色或测试存档名称：
场景与实际已有条件：
前一轮发生了什么：
我输入的原话：
实际回应和实际数值/物品变化：
我期望的对象、目的、方法：
应该怎么处理（允许列多个合理结果）：
问题分类（可多选）：理解错 / 没这个玩法 / 规则结算错 / 对白不连贯 / 太慢 / 不好玩
严重程度：误执行或事实错误 / 卡住无法继续 / 表达别扭但可继续
复现步骤或截图：
```

严重错误优先：没要求就执行、拒绝后仍写动作已发生、凭空道具/秘密、重复奖励、失败被说成成功。语言不够漂亮可后排，不要与规则破坏混成一类。

## D. 第三阶段：匿名比较模型

技术提供编号 A/B 的同题结果，不告诉策划具体模型名称。每条评价：理解是否正确、是否无谓追问、人物回应是否承接上下文、后果是否符合卡片、是否愿意继续玩。优先比较严重误解和端到端延迟，不能只选“文笔更好但规则乱来”的结果。

策划不用部署小模型、写训练脚本或分析 token 账单。产品负责人根据技术测量与体验评价选择上线方案；若小模型没有实测优势，保留现有模型也是有效结论。
