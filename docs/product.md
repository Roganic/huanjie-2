# 产品定义

阅读顺序：先看“当前目标”和“当前范围”，只有在需要推进产品决策时再补充细节。

> 2026-09-07 更新：基础 V1 已获用户试玩认可；当前进入受控 AI 主持阶段，范围见 [AI 主持 V2](ai-host-v2.md)。友方/中立攻击继续禁用，覆盖下文较早的允许攻击政策。编辑器、纯文本解析器和画布升级后置。

## 当前目标

构建一个 AI 跑团系统的本地 Web 原型，验证以下问题：

- AI 是否能稳定担任 GM
- 规则内核是否足够简单但仍然好玩
- 记忆 / RAG / 规则引擎的组合是否可行
- 多轮长流程体验是否成立

## 当前范围

- 单个项目工作区
- 本地 Web 原型
- 文档优先推进
- 规则研究与实现并行

## 实施顺序（2026-09-06 用户确认）

本文件作为产品范围依据，具体规则参考 [规则内核](rules-core.md)。历史里程碑的“完成”不替代当前验收；逐项状态、缺口和通过标准见 [能力验收清单](capability-acceptance.md)。

1. **补全基础能力**：沿用 React 文字跑团形态，完成角色、地图探索、背包装备、检定、战斗、简化成长与恢复、保存继续的闭环。
2. **留好接口**：随基础能力建设同步统一行动、状态和结果；文字、按钮及后续地图棋子操作使用相同规则，不等到更换呈现方式才整理。
3. **升级呈现**：基础验收后再转向可视化桌面跑团，增加地图与角色棋子的交互。具体引擎和空间规则届时确定。

模组、AI 叙事、记忆与开放探索仍是产品后续目标，在基础系统验收后推进；其与可视化呈现之间的具体排期尚未确定。基础阶段允许使用固定叙事验证规则。

现有三职业用于验证基础闭环；不据此扩大为完整职业构筑、复杂技能树或完整法术库。原文未确定的玩法保留为待定义项。

## 暂不做

2026-09-06 遭遇规则补充：用户确认允许攻击和平 NPC 并使场景转为危险；遭遇触发时全部敌人参战，不引入站位、远近距离、警戒或察觉。按先攻速度排序，保留敌人伤势、死亡、敌对和任务后果。当前采用速度＝敏捷修正，先攻＝d20＋速度；细则见 [场景与遭遇规则](world-encounters.md)。此前关于文字阶段移动/遭遇距离的设计建议以此为准。

- 多端 App
- 多服务复杂拆分
- 完整复刻任意一套原版规则
- 过早追求完备美术、世界观资产或上线级基础设施
