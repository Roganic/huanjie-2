### 前置：预算与模型基线

- 先实现持久费用记录、请求前预算预留和停止新请求的阈值，覆盖重试、解析修复、并发与未返回 usage 的请求；本地和线上共用本轮预算约束。
- 本轮项目模型 API 总预算 50 元，计划 45 元停止新请求、5 元留作账单差异余量。应用预算保护范围不能涵盖同账号其他应用的消费，结算仍需与供应商账单核对。
- 首批模型筛选预算不超过 2 元，优先验证已充值百炼。同一组对话、行动意图和故事解析题比较质量、耗时和真实 token 用量；只在不合格时增选模型。
- 不将 Coding Plan 的工具内订阅默认视为自建应用 API 套餐，不为优惠另行充值或购买。

### 第二阶段收口：可靠 AI 冒险

- 玩家表达、实际行动与已发生事实保持连贯；后续追问能够承接目标、NPC 身份、检定结果和事件。
- AI 提出行动和叙述，规则层决定检定、奖惩、事件和战斗；已结算的失败不能靠改写句子无限重投，模型不能凭叙述直接发放物品或推进任务。
- 完整跑通短篇三条路线，覆盖追问、失败推进、事件和存读档；降级结果或按钮代行不能冒充 AI 合格。
- 输出模型选型结论、失败样例、实际响应时间和费用，必要修复以共同架构与契约为单位。

### 第三阶段收口：完整游戏体验

- 复用已完成的主舞台、地图和面板，贯通角色创建、探索、对话、检定、战斗、成长、终章与继续冒险。
- 明确操作继续直接走规则；AI 等待、错误恢复和重复提交处理一致，技术解释收进详情。
- 游戏主舞台由游戏引擎组织场景、输入、地图镜头与反馈；地图改为不规则节点路网。规则仍复用同一后端，不能为引擎另写一套裁定。
- 桌面与手机端完整试玩，核对位置、目标、反馈和存档恢复。已有 DOM 工坊可独立保留，但主界面只加一个 Canvas 不算整体重构完成。

### 第四阶段收口：故事成为可玩模组

- 贯通原稿 → 模型故事结构 → 确定性编译/校验 → 草稿编辑 → 导入 → 独立冒险。
- 真实原稿生成必须保留人物关系、触发条件、失败后果和结局因果；有疑问需标出供作者确认，不静默删减故事。
- 复用已有分类编辑、草稿恢复和错误修复；用实际模型生成结果导入并试玩，不能用手工内置模组代替解析验收。
- 短篇《最后一盏渡灯》与中篇《潮汐之下的城》作为完整内容交付，保留原稿和可玩模组。

- 部署 Sites，在真实线上环境验证 AI、身份隔离、保存恢复、创作与冒险；密钥仅在服务端。
