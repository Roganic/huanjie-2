# 规则内核

阅读顺序：先看“V1 摘要”和“核心循环”，需要落地实现时再看“V1 机制包”和“模块边界”。

本文件用于沉淀“适合 AI 跑团”的第一版规则内核，而不是摘录原版规则书全文。

## V1 摘要

2026-09-06 用户确认覆盖项：遭遇内取消站位、距离、警戒和察觉，全部敌人同时参战；只按先攻排序，不实现战斗移动。友方/中立攻击按 2026-09-07 的新决定暂时禁用；本页下文历史“一次移动”等描述以 [场景与遭遇规则](world-encounters.md) 为准。

- 第一版采用“5e 判定语法 + OSE 流程结构”的轻量规则核
- 5e 主要贡献玩家熟悉的输入语言：六属性、属性修正、熟练、DC、优势 / 劣势
- OSE 主要贡献执行结构：先声明行动，再做必要裁定，再快速结算后果
- V1 只保留 AI 和玩家都容易稳定理解的高频机制：检定、命中、伤害、状态、资源推进、简化恢复
- 职业构筑、长法术清单、复杂反应链、THAC0、x-in-6 等多口径子系统不进入基础层

## 设计原则

- 简单、稳定、可执行
- 让模型负责叙事，让系统负责裁定
- 优先保留高频、易懂、易实现的机制
- 复杂例外和高负担联动延后
- 统一口径优先于原汁原味
- 能直接映射成结构化数据的机制优先

## 规则来源分工

### 5e 提供什么

- 六属性和属性调整值
- `d20 + 属性调整值 + 熟练加值` 的统一检定表达
- DC / AC 这类现代 d20 目标值语言
- 优势 / 劣势作为唯一通用情境修正
- 基础战斗语法：先攻、命中、伤害、HP

### OSE 提供什么

- 行动声明优先，而不是“默认先按按钮检定”
- 低例外密度和短流程
- 资源压力与时间推进的重要性
- 快速战斗与明确后果
- 让系统承担派生与结算，不让主持过程依赖大量查表

### 明确不直接照搬的内容

- 5e 的完整职业、专长、法术与复杂例外体系
- OSE 的 THAC0、降序 AC、x-in-6、2d6 士气等多口径并存表达
- 需要跨回合精确维护大量隐藏状态的复杂子系统

## V1 核心循环

1. 玩家声明行动
2. GM agent 提交结构化意图、规则动作或已有挑战；由规则决定是否执行和如何检定
3. 规则引擎返回结构化结果：成功 / 失败 / 代价 / 伤害 / 状态 / 资源变化
4. 事件系统结算或安排后果，GM agent 根据权威结果生成叙事反馈

当前完整接口见 [行动裁定与事件 V1](adjudication-events.md)。

这个循环的重点是：系统回答“怎么判”，GM agent 负责“怎么说”。

## 当前方向

- 以轻量 d20 体系为基础
- 吸收 5e 的玩家认知优势
- 吸收 OSE 的简洁和可执行性
- 强主题机制后续以模块形式加入

## V1 机制包

### 1. 属性与统一检定

- 保留六属性：力量、敏捷、体质、智力、感知、魅力
- 默认检定公式采用 `1d20 + 属性调整值 + 熟练加值（如适用）`
- 将通用属性检定、技能标签检定、豁免、攻击检定都收敛到同一主判定语言
- DC 先压缩成少量稳定档位，例如 10 / 15 / 20
- 只在结果不确定且后果明确时投骰

### 2. 熟练与标签

- 保留“熟练 / 不熟练”的二元区分
- 首版采用统一熟练加值，不处理复杂来源差异
- 不急着做完整技能列表，可先用少量高频能力标签承接常见行动

### 3. 优势 / 劣势

- 作为 V1 唯一通用情境修正
- 只有三态：优势 / 劣势 / 抵消后普通
- 不叠加多层数值修正，避免裁定漂移

### 4. 战斗与伤害

- 保留先攻，但实现上优先支持快速排序和短回合
- 使用升序 AC 命中口径
- 一轮默认一次主动作和一次移动
- 命中后直接结算伤害，优先影响 HP、状态和资源
- 附赠动作只在少量明确标记的能力中开放，不作为全局复杂度入口

### 5. 状态效果

- 第一版只保留少数高频状态，例如受限、倒地、失能、濒危
- 每个状态只保留一个核心效果，避免长段例外说明
- 状态解除条件应固定为回合结束、休整或明确动作

### 6. 资源、时间与恢复

- 至少跟踪 HP、关键物品槽、时间推进和基础补给压力
- 探索阶段要有时间成本，避免无限试错
- 恢复与成长先走低复杂度路线，例如短休整和里程碑推进
- 不在 V1 引入完整职业资源循环和完整法术经济

## V1 暂不纳入

- 完整自由建角
- 多职业、专长树、复杂职业联动
- 长法术清单与复杂施法细则
- 反应链、借机攻击、擒抱、推搡等高例外战斗规则
- THAC0、降序 AC、x-in-6、d20 向下等旧式并存口径
- 高频查表子系统
- 多单位管理、完整士气、追逐、遭遇距离等扩展流程

## 模块边界

### 内核负责

- 统一检定
- 命中与伤害
- HP 与基础死亡后果
- 少量状态
- 基础资源与时间推进
- 简化恢复

### 场景 / 扩展模块负责

- 法术系统
- 职业特性和成长差异
- 探索专题流程，如追逐、潜行、士气、遭遇距离
- 社交、调查、强主题世界观机制

## 实现提示

- 数据结构应围绕“动作输入”和“裁定结果”设计，而不是围绕整本规则书建模
- 派生值与结算优先交给系统，不让 GM agent 手工查表或手算
- 如果一个机制不能在几条固定字段里表达清楚，就不应进入 V1 基础层
- 后端优先落地的对象应包括：`ability_scores`、`ability_modifiers`、`proficiency_bonus`、`advantage_state`、`dc`、`ac`、`hp`、`initiative`、`action_budget`、`conditions`、`resources`

## 当前未决问题

- 技能标签是否直接压缩为项目自定义集合
- V1 是否允许少量模板化法术角色进入原型
- `0 HP` 是直接死亡，还是改成更宽松的濒死缓冲
- 资源压力要做到什么程度，才不会拖慢本地 Web 原型体验
