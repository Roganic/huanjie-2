# 2026-03-21 dnd-rules-analysis

## 目标

- 从 DND SRD 中提炼适合 AI 跑团 MVP 且对玩家友好的规则机制
- 明确回答角色创建、核心检定、战斗状态、AI 易错点、保留项、延后项这 6 个问题

## 做了什么

- 读取并比对 SRD 5.2.1 与 SRD 5.1 的核心章节
- 重点检查了角色创建、D20 检定、动作经济、战斗、伤害与治疗、专注和条件相关内容
- 在 `research/notes/` 新增分析笔记
- 在 `research/extracts/` 新增结构化提炼结果，方便后续整合者直接引用

## 结论

- DND SRD 最值得保留的是统一 d20 判定语言，而不是完整职业与法术体系
- 角色创建的完整流程对 MVP 偏重，尤其是施法职业、专长和自由组合会快速抬高复杂度
- 战斗的基础轮转可以保留，但条件、专注、反应、擒抱和伤害例外应显式裁剪
- AI 最容易在跨回合持续状态、例外覆盖一般规则和施法资源管理上出错
- MVP 适合采用“5e 语法 + 压缩建角 + 最小战斗闭环 + 结构化状态托管”的方案

## 未决问题

- 是否要保留附赠动作作为通用槽位，还是仅在少数能力上显式开放
- 首版是否允许任何法术角色进入 MVP，还是先只做非施法模板
- 条件集合应该压缩到几个最小状态，哪些可以延后到战斗增强模块
- 是否要进一步对照 OSE，确定哪些战斗复杂度可以直接用更简方案替代

## 下一步建议

- 基于本次结论，整理一版最小状态表和最小动作经济表
- 为后端准备统一判定和战斗状态的数据样例
- 如果后续要继续做 DND 方向研究，优先补“条件 / 专注 / 借机攻击 / 擒抱”的结构化测试案例
