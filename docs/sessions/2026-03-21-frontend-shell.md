# 2026-03-21 Frontend Shell

## 目标

在 `app/frontend/` 建立最小可运行的前端壳子，为 AI 跑团原型准备 UI 基础。

## 做了什么

1. **技术选型**：确定 Vite + React + TypeScript
   - React 生态成熟，AI 辅助编码效果好
   - Vite 零配置即可启动，HMR 快
   - TypeScript 有助于跨 session 理解代码
   - 暂不引入额外依赖（路由、状态管理、UI 库）

2. **项目初始化**：用 `create-vite` 脚手架生成基础结构，清理模板代码

3. **三栏布局实现**：
   - **左侧栏**：场景列表、队伍成员（静态 mock）
   - **中央聊天区**：GM/玩家对话流，带输入框和发送按钮
   - **右侧状态面板**：角色属性、能力值、事件日志
   - 输入后有 mock GM 回复（延迟 600ms 返回占位文本）

4. **视觉风格**：深色主题，适合跑团氛围的配色（深蓝/暗紫基调，红色强调色）

5. **文档更新**：
   - `docs/tech-choices.md`：补充前端框架选择和理由
   - `app/README.md`：补充前端启动说明

## 结论

- 前端壳子可本地运行（`npm run dev`），构建通过
- 三栏布局覆盖了跑团原型的核心 UI 区域：叙事对话、角色状态、场景导航
- 纯静态 mock 数据，未接后端

## 未决问题

- 聊天消息是否需要支持 Markdown 渲染（GM 叙事可能需要富文本）
- 骰子结果是否在聊天流内展示还是独立区域
- 状态面板的数据结构需要和规则内核对齐
- 移动端适配暂未考虑

## 下一步建议

- 接入后端 API 后替换 mock GM 回复为流式响应
- 根据规则内核定义角色数据结构（目前是硬编码 mock）
- 考虑增加骰子动画/结果展示组件
- 如需多场景切换，引入简单路由
