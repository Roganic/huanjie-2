# 2026-03-21 OSE Rules Analysis

## 目标

- 基于 OSE SRD 提炼适合 AI 稳定执行、低复杂度的机制
- 明确哪些规则适合进入 MVP，哪些应砍掉或延后
- 不直接修改 `docs/rules-core.md`，只提供分析和结构化提炼

## 做了什么

- 检查当前 worktree 的允许写入范围
- 核对本地 `research/raw/ose/`，确认未找到用户提到的 HTML 导出文件
- 改为读取官方 OSE SRD 在线页面，重点查看角色创建、属性、属性检定、豁免、战斗、遭遇、士气、伤害与死亡
- 在 `research/notes/` 新增分析笔记
- 在 `research/extracts/` 新增结构化提炼结果

## 结论

- OSE 的优势是规则结构短、边界清楚、资源压力明确，不是“完全无复杂度”
- 对 AI 最危险的部分，是多种判定口径并存和 THAC0 / 降序 AC 这类旧式表达
- 适合进入 MVP 的，是行动声明优先、统一轻量检定、边先攻、快战斗、HP/伤害/死亡和基础资源压力
- 应砍掉或延后的，是 THAC0、完整查表流程、细碎战术修正、完整法术细则和多单位管理

## 未决问题

- 是否保留 OSE 风格的高致死性，还是在 MVP 中加入更宽松的濒死缓冲
- 探索压力要保留到什么强度，才不会拖慢本地 Web 原型体验
- 士气、惊奇、遭遇距离等遭遇层机制是否进入首版，还是作为后续扩展
