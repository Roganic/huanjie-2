## 修复的实际问题

- 文字拾取、装备、卸下、使用与背包按钮共用 `game/inventory.py`。治疗物品按 ID 扣除一件；满血拒绝消耗；自定义“月光茶”等物品在探索和战斗中的文字操作也生效。
- 通用行动曾由编排层和路由各记一次历史，现只记录一次。四组重复的自动成功、属性推断、难度、攻击属性规则改为调用同一实现；普通“环顾四周”不再随机要求力量检定。
- 场景检定实际应用时间、伤害、物品与线索效果。成功后保存已完成记录，重复调查不再发奖或推进时间；失败可重试。奖励物品复制自当前内容包，不共享可变对象。
- 武器支持内容格式允许的 `1d6+2` 等伤害骰，避免解析崩溃；攻击结果叙事使用当前武器名称。请求提供的场景/角色名称不替代真实状态，携带武器的攻击也必须进入实际遭遇处理。
- 旧敌方 AI 不能选择 HP 为零的目标，不能由无法行动的敌人发动攻击。角色倒下时文字入口拒绝操作。
- 损坏存档明确返回格式错误，不覆盖现有进度；启动遇到损坏旧存档不会导致服务启动失败。重置当前进度保留手动存档，也不会删除其他冒险的旧存档。

## 场景互动与未来接口

`ModulePack.scenes[*].interactions` 可配置稳定 ID、名称、行动文本、技能、DC、成功/失败叙事、失败伤害及物品/线索奖励；校验技能名称、重复 ID 与奖励引用。仍使用兼容的 Schema v1（新增可选字段）。

每次未完成互动耗时 1；失败伤害默认为 0。成功将 ID 写入会话的 `completed_interactions[scene_id]`；场景指引只显示未完成互动。该记录、线索和奖励随完整存档恢复。

内置内容版本 1.0.1 在地下城入口提供“检查废弃补给箱”和“辨认古老碑文”。已有冒险保留自己的内容快照，不自动替换旧模组；新冒险使用新版内容。

后续编辑器和纯文本解析器都应输出草稿，通过 `/modules/validate`，再导入、启动新冒险。`StoryParser.parse(source) -> dict`、模块 Schema、校验和导入接口保持可用；自然语言解析和编辑 UI 均后置。
